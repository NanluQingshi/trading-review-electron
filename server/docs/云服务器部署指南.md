# 激活服务器云部署指南

本文档说明如何将 TradingReview 激活服务器部署到云服务器（阿里云、腾讯云、AWS 等）。

---

## 一、前置准备

### 1. 云服务器

- 购买一台云服务器（1 核 1G 即可）
- 系统推荐：Ubuntu 22.04 或 CentOS 7+
- 确保开放端口：80（HTTP）、443（HTTPS）、22（SSH）

### 2. 域名（可选但推荐）

- 购买域名并完成备案（国内服务器需备案）
- 将域名解析到服务器公网 IP

---

## 二、部署步骤

### 步骤 1：连接服务器

```bash
ssh root@你的服务器IP
```

### 步骤 2：安装 Node.js

**Ubuntu / Debian：**

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v   # 验证安装
```

**CentOS：**

```bash
curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash -
sudo yum install -y nodejs
node -v
```

### 步骤 3：上传项目到服务器

**方式 A：使用 SCP**

在本地项目目录执行：

```bash
cd /path/to/trading-review
scp -r server root@你的服务器IP:/opt/trading-review-activation
```

**方式 B：使用 Git**

在服务器上：

```bash
cd /opt
git clone 你的仓库地址 trading-review-activation
cd trading-review-activation/server
```

**方式 C：使用 rsync**

```bash
rsync -avz --exclude 'node_modules' server/ root@你的服务器IP:/opt/trading-review-activation/
```

### 步骤 4：安装依赖并启动

```bash
cd /opt/trading-review-activation
npm install --production
npm start
```

验证：`curl http://localhost:3001/api/activate` 应返回 400（缺少 body 属正常）。

---

## 三、使用 PM2 保持进程常驻

安装 PM2：

```bash
sudo npm install -g pm2
```

启动服务：

```bash
cd /opt/trading-review-activation
pm2 start activation-server.js --name activation-server
pm2 save
pm2 startup   # 按提示执行命令，实现开机自启
```

常用命令：

```bash
pm2 status          # 查看状态
pm2 logs            # 查看日志
pm2 restart activation-server   # 重启
```

## 四、配置 Nginx 反向代理 + HTTPS

### 1. 安装 Nginx

```bash
# Ubuntu
sudo apt update && sudo apt install -y nginx

# CentOS
sudo yum install -y nginx
```

### 2. 配置 Nginx

创建配置文件（替换 `your-domain.com` 为你的域名）：

```bash
sudo nano /etc/nginx/sites-available/activation
```

内容：

```nginx
server {
    listen 80;
    server_name your-domain.com;   # 或使用服务器 IP

    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

启用配置：

```bash
# Ubuntu
sudo ln -s /etc/nginx/sites-available/activation /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

# CentOS（配置文件路径可能为 /etc/nginx/conf.d/activation.conf）
sudo nginx -t && sudo systemctl reload nginx
```

### 3. 配置 HTTPS（推荐）

使用 Let's Encrypt 免费证书：

```bash
sudo apt install -y certbot python3-certbot-nginx   # Ubuntu
sudo certbot --nginx -d your-domain.com
```

按提示完成验证后，Nginx 会自动配置 HTTPS。

## 五、应用端配置

在项目根目录 `.env` 中设置（**打包前必须配置**，该值会写入打包产物）：

```env
ACTIVATION_SERVER_URL=https://your-domain.com
```

若使用 IP 且未配置 HTTPS：

```env
ACTIVATION_SERVER_URL=http://你的服务器IP:3001
```

## 六、防火墙配置

```bash
# Ubuntu (ufw)
sudo ufw allow 22
sudo ufw allow 80
sudo ufw allow 443
sudo ufw enable

# CentOS (firewalld)
sudo firewall-cmd --permanent --add-service=ssh
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload
```

云厂商控制台的安全组也需放行 80、443 端口。

## 七、数据与备份

- **数据库路径**：`/opt/trading-review-activation/data/activation.db`
- **备份命令**：

```bash
cp /opt/trading-review-activation/data/activation.db /backup/activation-$(date +%Y%m%d).db
```

建议用 cron 定期备份：

```bash
crontab -e
# 每天凌晨 2 点备份
0 2 * * * cp /opt/trading-review-activation/data/activation.db /backup/activation-$(date +\%Y\%m\%d).db
```

## 八、如何更新部署（代码有改动时）

当 `activation-server.js` 或数据库逻辑有更新时，按以下步骤操作：

```bash
# 1. 在本地将 server 目录同步到服务器（排除 node_modules）
rsync -avz --exclude 'node_modules' --exclude 'data' server/ root@你的服务器IP:/opt/trading-review-activation/

# 2. SSH 登录服务器
ssh root@你的服务器IP

# 3. 进入目录并重启服务
cd /opt/trading-review-activation
pm2 restart activation-server

# 4. 查看日志确认启动正常
pm2 logs activation-server --lines 20
```

**注意**：
- `--exclude 'data'` 会保留服务器上的 `data/activation.db`，不覆盖
- 若数据库表结构有变更，服务启动时会**自动迁移**旧表到新结构，无需手动操作

## 十、常见问题

**Q：激活码无效？**  
A：检查 `data/activation.db` 中 `activation_codes` 表是否有对应 code，且 `used=0`。

**Q：跨域错误？**  
A：服务端已启用 CORS，若仍有问题，检查 Nginx 是否正确转发请求。

**Q：HTTPS 证书过期？**  
A：`certbot renew` 可续期，建议配置 `certbot renew --dry-run` 的 cron 任务。
