# 激活服务器配置说明

TradingReview 使用「激活码」进行一次性激活，激活时需要联网验证，激活成功后即可离线使用。

## 一、应用端配置

### 1. 配置激活服务器地址

在项目根目录的 `.env` 文件中设置**服务器 base URL**（不含接口路径，`/api/activate` 在代码中）：

```env
ACTIVATION_SERVER_URL=https://你的服务器地址
```

例如本地测试：

```env
ACTIVATION_SERVER_URL=http://localhost:3001
```

### 2. 打包时配置

**重要**：打包前确保 `ACTIVATION_SERVER_URL` 已正确设置。该值会在 `npm run make` 时**写入到打包产物**中，因此：
- 本地开发：`.env` 在运行时加载
- 本地打包：必须在 `.env` 中配置好
- GitHub CI/CD 打包：必须在仓库 Secrets 中配置（见下方）

### 3. GitHub Actions 配置（CI/CD 打包）

若使用 GitHub Actions 自动打包（push tag 触发），需在仓库中配置 Secret：

1. 打开仓库 → **Settings** → **Secrets and variables** → **Actions**
2. 点击 **New repository secret**
3. Name：`ACTIVATION_SERVER_URL`
4. Value：你的激活服务器地址，如 `http://31.97.179.228:3001`

配置后，每次 CI 打包时会将此值注入到产物中。

## 二、服务器端实现

### 接口规范

**请求**

- 方法：`POST`
- URL：`/api/activate`（在 App 端代码中固定）
- Content-Type：`application/json`
- Body 示例：

```json
{
  "code": "用户输入的激活码",
  "appVersion": "1.0.0",
  "platform": "darwin"
}
```

**成功响应**（HTTP 200）

```json
{
  "success": true,
  "message": "激活成功"
}
```

或：

```json
{
  "valid": true
}
```

**失败响应**（HTTP 4xx）

```json
{
  "success": false,
  "message": "激活码无效或已被使用"
}
```

### 激活码「一次生效」逻辑

服务器需要维护已发放的激活码列表，并在每次验证时：

1. 校验激活码是否在预置列表中
2. 校验该激活码是否已被使用
3. 若有效且未使用：标记为已使用，返回成功
4. 若无效或已使用：返回失败

## 三、使用项目自带的激活服务器

项目已包含激活服务器，使用 **SQLite** 持久化存储，重启不丢失数据：

```bash
cd server
npm install
npm start
```

- 数据库文件：`server/data/activation.db`
- 默认预置激活码：`TR-2026-DEMO-001`、`TR-2026-DEMO-002`、`TR-2026-DEMO-003`
- 新增激活码：直接往数据库 `activation_codes` 表插入 `code` 即可

在 `.env` 中设置：

```env
ACTIVATION_SERVER_URL=http://localhost:3001
```

## 四、自建服务器示例（Node.js + Express）

如需自行实现，可参考以下代码。在项目外新建目录：

```bash
mkdir activation-server && cd activation-server
npm init -y
npm install express cors
```

创建 `server.js`：

```javascript
const express = require('express');
const cors = require('cors');

const app = express();
app.use(cors());
app.use(express.json());

// 预置的激活码（实际部署时建议从数据库或配置文件读取）
const VALID_CODES = new Set(['CODE-XXXX-YYYY', 'CODE-AAAA-BBBB']);

// 已使用的激活码（实际部署时建议用数据库存储）
const usedCodes = new Set();

app.post('/api/activate', (req, res) => {
  const { code } = req.body;

  if (!code || typeof code !== 'string') {
    return res.status(400).json({
      success: false,
      message: '请提供有效的激活码',
    });
  }

  const trimmedCode = code.trim();

  if (!VALID_CODES.has(trimmedCode)) {
    return res.status(400).json({
      success: false,
      message: '激活码无效',
    });
  }

  if (usedCodes.has(trimmedCode)) {
    return res.status(400).json({
      success: false,
      message: '该激活码已被使用',
    });
  }

  // 标记为已使用
  usedCodes.add(trimmedCode);

  return res.json({
    success: true,
    message: '激活成功',
  });
});

const PORT = process.env.PORT || 3001;
app.listen(PORT, () => {
  console.log(`激活服务运行在 http://localhost:${PORT}`);
});
```

运行：

```bash
node server.js
```

## 五、如何添加新激活码

服务器使用 SQLite，激活码存在 `server/data/activation.db` 的 `activation_codes` 表中。

**方式一：用 SQL 工具**（如 DB Browser for SQLite）

```sql
INSERT INTO activation_codes (code) VALUES ('YOUR-NEW-CODE-001');
```

**方式二：用命令行**

```bash
cd server
sqlite3 data/activation.db "INSERT INTO activation_codes (code) VALUES ('YOUR-NEW-CODE-001');"
```

## 六、部署建议

1. **生产环境**：将服务器部署到云服务器（如阿里云、腾讯云），并配置 HTTPS。
2. **数据持久化**：已使用 SQLite，`server/data/activation.db` 会随服务一起部署，重启不丢失。
3. **安全**：可增加 IP 限流、请求签名等，防止暴力破解。
4. **备份**：定期备份已使用激活码记录，便于审计和排查问题。

## 六、测试流程

1. 启动激活服务器：`node server.js`
2. 在 `.env` 中设置 `ACTIVATION_SERVER_URL=http://localhost:3001`
3. 启动 TradingReview：`npm start`
4. 在激活页面输入预置的激活码（如 `CODE-XXXX-YYYY`）
5. 验证成功后，应用可正常使用；关闭网络后仍可离线使用
